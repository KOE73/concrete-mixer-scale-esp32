## Краткое резюме

Задача: сделать весовую подставку под бытовую бетономешалку на **N тензодатчиках**,
с передачей данных по **Wi-Fi** на ПК и анализом в C#.

Количество датчиков может быть N, но в примеры основанны на 3 датчиках.

Главный вывод: в этой системе не надо мыслить как в статических весах.
Бетономешалка крутится, нагрузка гуляет, отдельные датчики постоянно перераспределяются.
Поэтому рабочая модель — **виртуальный датчик**:

Последовательность
Дано датчики raw1/raw2/raw3
- rawSum - raw сумма всех датчиков
- фильтр удаление цифровых глюков, если не прошел, просто выкидываем этот сэмпл и в MA ничего не кладём
- cleanSum - круговой массив после фильтра, который идёт в MA. для MA10 хватит 100,
   но чо экономить память не надо, можно 600. Внимание суммы большие надо хранить в 64-битной переменной,
   а не 32-битной, чтобы не было переполнения.
- MA1/MA3/MA5/MA10/MA30
- zero по пустой крутящейся мешалке
- рабочие попугаи / условные кг / контрольные точки

## Проблемы

### 1. Динамическая нагрузка

Барабан вращается, смесь перекатывается, рама вибрирует.
Индивидуальный offset каждого датчика хорош для статических весов,
но здесь отдельный канал сам по себе малоинформативен.

Вывод: управление делать не по отдельным каналам, а по суммарному виртуальному сигналу.

### 2. Останавливать бетономешалку с грузом нельзя

Значит вся логика должна работать при вращении.
Нельзя строить алгоритм вокруг “остановил → дождался стабильности → измерил”.

Вывод: zero, контрольные точки и текущий вес должны сниматься в том же режиме,
 в котором идёт работа: **пустая мешалка крутится → zero**, загруженная мешалка крутится → измерение.


### 3. Есть одиночные цифровые выбросы

По графикам видно, что выбросы не похожи на физику. Это одиночные пики в миллионы вверх/вниз, иногда около пределов 24-битного signed диапазона.

Вероятные причины:

- битовый срыв чтения HX711/АЦП
- чтение не по ready
- ошибка sign extension
- Wi-Fi/interrupt во время bit-bang чтения
- помехи по питанию/земле
- длинные провода SCK/DOUT
- плохой контакт

Вывод: такие значения надо не сглаживать, а **выкидывать до MA**.

Вывод: фильтр должен ловить только **физически невозможные** скачки.
 Не надо строить сложный soft/pending/median-фильтр.


### 5. Рецепт не фиксированный

Последовательность загрузки может меняться. Обычно:

1. вода примерно 60%
1. щебень весь
1. остаток воды
1. цемент примерно полмешка
1. песок

Но это не должно быть жёстко зашито.

Вывод: нужна не модель “рецепта”, а массив **контрольных точек** до 16 штук.


## Решения

### 1. Разделить программы

Сделать отдельные программы:

- MixerScale.UdpRecorder - логирует принятые данные в файлы
- MixerScale.Analyzer - для анализа логов
- MixerScale.Controller - для live управления. отображает все для правильной работы,
    позволяет делать zero, сохранять контрольные точки, выбирать текущую точку и
    показывать состояние относительно неё.


### 3. Фильтр выбросов

Алгоритм:
- считаем среднее и максимальную дельту между соседними сэмплами в накопленном массиве
- если новый сэмпл отличается от последнего хорошего на больше, чем `hardDelta`,
    то это глюк, его выкидываем вообще, дальше все пропускам.

Не использовать median, soft limit, pending-подтверждение. Только hard reject.

Порог сделать настраиваемым. Начать примерно с:

hardDelta = 500 000 ... 1 000 000 raw units

Потом уточнить по реальным логам работающей мешалки.


### 4. MA считать по cleanSum

`rawSum` нужен для лога.
`cleanSum` — вход в MA.

MA окна не фиксированные можно любые делать по умолчанию:
- MA1  = 1 секунда
- MA3  = 3 секунды
- MA5  = 5 секунд
- MA10 = 10 секунд
- MA30 = 30 секунд
- MA60 = 60 секунд


### 5. Zero делать после MA

Zero не индивидуальный по датчикам. Zero — это базовый уровень виртуального датчика в рабочем режиме.

Практически:

- пустая мешалка крутится
- жмём ZERO
- берём MAn как ноль. т.е. zero = MAn в момент нажатия ZERO.
  Т.е. надо несколько кнопок ZERO для разных MA. Просто я визуально по графикам пойму что мне лучше.

---

### 6. Контрольные точки

Сделать массив максимум на 16 точек.

Режим обучения:
- пустой барабан → ZERO
- налил первую воду → SAVE POINT
- засыпал щебень → SAVE POINT
- долил воду → SAVE POINT
- цемент → SAVE POINT
- песок → SAVE POINT
- сохранил профиль

Сохранять не рецепт, а контрольные значения:
в точке хранится значение и можно добавить краткое примесчание для себя, типа "вода 60%" или "щебень весь".

```text
point[0]
point[1]
point[2]
...
```

Единицы хранения — raw.

### Попугаи

Реальные КГ пожалуй не достижимы, потому что мешалка крутится, смесь перекатывается, рама вибрирует.

Хочу иметь несколько условных попугаев
- условный 1 кг
- лопата
- ведро

т.е. массив коэффициентов для перевода raw в эти условные единицы. в еденицах еще хранить до 5 символов для ед измерения.
