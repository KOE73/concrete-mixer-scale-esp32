# UDP CSV contract

Этот документ является центральным описанием CSV-формата для сырой UDP-телеметрии весов. Прошивка, UDP-приемник и Analyzer должны опираться на него, а не заводить локальные варианты формата.

Рабочая модель веса — один виртуальный датчик:

```text
raw_sum -> hard reject -> clean_sum -> MA
```

Отдельные HX711 входы являются только физическим способом получить `raw_sum`. Они не публикуются в UDP CSV, Web live API или Controller state как отдельные рабочие каналы.

## Формат строки

```csv
scale_id,seq,ms,raw_sum,kg_sum,flags[,win1,ma1,win2,ma2,...]
```

## Поля

| Поле | Обязательное | Тип | Смысл |
| --- | --- | --- | --- |
| `scale_id` | Да | uint32, больше 0 | Числовой идентификатор весов. |
| `seq` | Да | uint64 | Монотонный номер логического сэмпла прошивки. |
| `ms` | Да | uint64 | Время ESP32 в миллисекундах. |
| `raw_sum` | Да | int64 | Сырая сумма всех физических HX711 входов текущего сэмпла. Не фильтруется. |
| `kg_sum` | Да | float | Значение виртуального датчика после `sumOffset/sumScale`. Название оставлено как старое поле CSV. |
| `flags` | Да | строка без запятых | `valid`, `invalid|sensor_error`, `invalid|hard_reject` и будущие флаги. |
| `winN,maN` | Нет | int,float пары | Дополнительные MA окна: размер окна в секундах и значение MA. |

## Правила

- `raw_sum` всегда считается в 64-bit.
- Hard reject не меняет `raw_sum`; он только запрещает сэмплу попасть в `clean_sum` и MA.
- `clean_sum` является производным значением и не пишется обязательным полем UDP CSV.
- Recorder только пишет строки и не пересчитывает управление.
- Analyzer пересчитывает `clean_sum` и MA по `raw_sum` из логов.
